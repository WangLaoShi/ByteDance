## 2. 生成岗位主表 `岗位主表`

**粒度为每个有效岗位 ID 一行。** 保留原始字段和以下分析字段。

### 主键和重复记录

1. 缺失或精度可疑的 ID 写入 `异常明细`，从正式岗位主表排除。
2. 同一 ID 的业务字段完全相同，保留源行号最小的一条，其余记录计为重复。
3. 同一 ID 来自不同抓取时间，主表取最新一条，并保留 `source_row`。如果全量确实包含多个抓取时间，另输出 `岗位快照`，粒度为 `id + fetched_at`，供后续判断是否可做跨期分析。
4. 同一 ID 在同一抓取时间的业务字段互相冲突，记录所有相关源行号及冲突字段。若该冲突涉及此 ID 最新的抓取记录，则暂时排除该岗位，避免随意挑一条。抓取时间缺失导致无法判断先后时，按冲突处理。
5. 单独检查同一 `code` 对应多个 `id` 的情况，写入报告。相同标题的不同 ID 继续保留。

### 招聘分组

- 使用 `portal_name` 和 `recruit_type_name` 生成 `recruit_group`。预期组合为「社招正式」「校招正式」「校招实习」。
- 交叉核对 `portal_type`、`recruit_type_id`、`recruit_parent_name` 与名称的对应关系。未知组合或字段冲突保留原值，将 `recruit_group` 标为「待确认」，并记录原因。
- 保留 `job_subject_name`。新增 `project_status`，区分「已填写」「不适用」「待确认」。只有全量校验支持时，才把社招的项目空值标为「不适用」。

### 岗位分类

- 保留 `category_id`、`category_name`、`category_parent_name`，新增 `analysis_category_l1`、`analysis_category_l2`、`category_mapping_status`。
- 按 `category_id` 统计原类别名和上级名。若同一 ID 只有一个非空上级，且类别名一致，可用该上级补齐空值，标记「同 ID 补齐」。
- 上级全部为空的类别，只有在人工映射明确确认它是顶级类时，才用自身作为大类。其余进入「待确认」。同一 ID 有多个上级或类别名称冲突时，写入异常，等待确认。
- 输出 `分类映射` 工作表，包含原类别 ID、原名称、原上级、分析大类、分析细类、映射状态、岗位数。支持通过可选的 `--category-map` 参数传入人工映射 CSV。人工映射的类别 ID 必须唯一。
- 每条岗位只进入一条「大类 → 细类」路径。保留「待确认」分组，使拆解树、旭日图和矩阵树图能对回主表总数。

### 时间转换

- `publish_time` 按 Unix **毫秒**时间戳解析，先按 UTC 转换，再转为 `Asia/Shanghai`。输出 `publish_datetime`、`publish_date`、`publish_month`。`publish_month` 用月初日期表示，便于 QuickBI 排序和筛选。
- `publish_time` 使用 https://github.com/WangLaoShi/date-dimensions 中的方法进行扩展，我们可以在后续进行进一步的维度分析。
- `fetched_at` 按带时区的 ISO 日期时间解析，统一到北京时间，输出 `fetched_datetime`。Excel 中写入转换后的本地日期时间，并在字段字典注明时区。保留两个原始字段。
- 新增 `publish_time_status`，区分「有效」「缺失」「格式错误」「晚于抓取时间」「早期记录待复核」。早期复核阈值可配置，报告记录实际使用的阈值。早期记录保留并单独标记，待业务确认。时间异常只影响时间图的筛选，岗位仍可参与其他有效维度的统计。
- 报告列出抓取批次数、各批记录量、有效发布时间范围以及时间异常量。单批数据的时间图统一表述为「本次抓取岗位按发布月份分布」。

## 3. 生成岗位—城市表 `岗位城市`

**粒度为 `id + 标准城市` 一行。**

- 优先拆分 `city_names`。处理 `、`、中英文逗号、中英文分号等明确分隔符，去除每项首尾空白，过滤空项并去重。不要按空格拆分城市。
- `city_names` 为空时，可回退使用 `city_name`，并用 `city_source` 标记来源。如果两者都为空，岗位仍保留在主表，城市缺失写入异常。
- 保留 `city_name` 为源表单城市字段。只有业务定义确认它代表主城市时，才用于主城市占比。如果 `city_name` 不在 `city_names` 拆出的集合中，记录差异供核对。
- 支持通过 `--city-map` 传入城市映射 CSV，字段至少包含 `city_raw, city_standard, province, country_or_region, geo_code`。没有映射时保留原城市名及「待映射」状态，省份和地图编码留空。只允许通过明确映射合并城市别名，避免仅靠去除「市」字合并同名地区。
- 表内带上 `id`、城市相关字段、招聘分组、大类、细类、发布月及时间状态，使 QuickBI 导入后可直接做交叉表、排行、地图和城市到岗位大类的流向图。岗位总量始终按 ID 去重统计。城市间允许重复覆盖，跨城市总计重新对 ID 去重。
- 使用 https://github.com/WangLaoShi/address-dimensions 对 address 进行拆解，之后可以作为重点分析的对象。
